# Промт: админка для сайта-портфолио

Сделай так, чтобы я могла менять тексты, кейсы, услуги, цены, вопросы,
фото и контакты сайта в браузере, без кода. Сайт после этого должен
выглядеть и работать точно так же, как сейчас.

Работаем по правилам из CLAUDE.md: по одному шагу, после каждого шага
покажи результат и жди моего «ок», после «ок» — git commit.

В CLAUDE.md и промт.md написано «без сборщиков, без админки». Эти пункты
больше не действуют: теперь делаем по этому файлу. В конце обнови CLAUDE.md
(шаг 7).

## Как будет устроено

```
data/ru/*.json, data/en/*.json   ← весь контент (его правит админка)
templates/                       ← вёрстка: шаблоны блоков, шапка, подвал
build.py                         ← собирает data + templates → dist/
dist/                            ← готовый сайт: обычный HTML, его выкладываем
.pages.yml                       ← настройка админки Pages CMS
```

Цепочка: правка в админке → коммит в GitHub → автосборка `build.py`
→ обновлённый сайт на хостинге.

Весь текст должен оказаться в готовом HTML (для поисковиков), а не
подгружаться через JavaScript.

## Шаг 0. Подготовка

- `git status` должен быть чистым. Если адаптив не закоммичен — остановись
  и скажи мне.
- Создай ветку `admin` и работай в ней: `git checkout -b admin`.
  В main ничего не меняй до шага 6.
- Ничего не удаляй. Старые index.html и en/index.html остаются как эталон
  для сравнения, пока я не скажу иначе.
- Составь таблицу всего, что можно менять, по index.html и en/index.html:

  | Блок | Что меняется | Тип поля | Ограничение |
  |---|---|---|---|
  | Первый экран | Заголовок | строка | до 60 символов |
  | Кейсы | Список: название, теги, задача, картинка, ссылка, «широкий» | список | … |
  | … | | | |

  Типы: строка, длинный текст, картинка, ссылка, список, да/нет.
  Ограничения подбери так, чтобы длинный текст не ломал вёрстку.
  Что НЕ меняется в админке: структура, порядок блоков, дизайн, токены.
- Жди «ок» по таблице.

## Шаг 1. Генератор build.py

- Python 3 + Jinja2 (единственная зависимость, в `requirements.txt`).
  Автоэкранирование включено, чтобы текст из админки не ломал HTML.
- `python build.py` собирает `dist/index.html` (русская версия)
  и `dist/en/index.html` (английская) из общих шаблонов и `data/ru`, `data/en`.
- Копирует в `dist/` папку assets, styles.css, tokens.css, script.js.
- К ссылкам на CSS и JS добавляет `?v=дата-сборки`.
- Шапка и подвал описаны один раз и подставляются в обе версии.
- Пустое поле не ломает вёрстку: блок или элемент просто не выводится.
- Блок «Отзывы» показывается, только если в данных есть 3+ отзыва
  и стоит флажок «Показывать блок». Пункт меню — по тому же правилу.
- Комментарии в коде на русском, короткие.
- Покажи каркас (пустые шаблоны + build.py + один тестовый блок) и жди «ок».

## Шаг 2. Перенос контента, по одному блоку

Для каждого блока по порядку страницы:
1. Вынеси тексты блока в `data/ru/<блок>.json` и `data/en/<блок>.json`.
   Тексты переносятся дословно, ничего не переписывай.
2. Сделай шаблон блока в `templates/`.
3. Запусти `python build.py`.
4. Сравни `dist/` с эталоном: текст блока совпадает слово в слово,
   на 375 и 1280 блок выглядит так же. Отчёт: «что перенесено / расхождения».
5. Жди «ок», затем commit, например: «Админка: кейсы в данные».

Имена полей в JSON — на английском, понятные (`title`, `task`, `image`).

## Шаг 3. Админка Pages CMS

- Сначала прочитай актуальную документацию Pages CMS (pagescms.org/docs)
  и напиши `.pages.yml` строго по ней. Не угадывай синтаксис.
- Отдельные разделы для русской и английской версии.
- Картинки загружаются в `assets/img/`.
- Подписи полей по-русски и понятно: «Заголовок первого экрана»,
  «Фото кейса», а не `hero_title`. У каждого поля подсказка
  и ограничения из таблицы шага 0 (длина, формат картинки).
- Списки (кейсы, услуги, вопросы, пункты «Обо мне», отзывы) можно
  добавлять, удалять и менять местами.
- Напиши мне по шагам, что сделать самой: войти в Pages CMS через GitHub,
  дать доступ к репозиторию и т.д. Сама ты не входишь и ничего не подтверждаешь.
- Жди «ок».

## Шаг 5. Проверка админки

Проверь и дай отчёт таблицей:
- поменять заголовок → сайт обновился;
- добавить кейс с картинкой → появился в нужном месте, сетка не сломалась;
- удалить кейс, поменять порядок;
- оставить поле пустым → вёрстка цела;
- вставить очень длинный текст → ограничение сработало или вёрстка цела;
- английская версия обновляется отдельно от русской;
- адаптив на 375 и 1280 после всех правок такой же, как до.
